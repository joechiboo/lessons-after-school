# 敏捷篇

把 Scrum 帶進一個十人資訊室的過程。哪些做到了,哪些還沒做到,做的時候踩到什麼。

不是 Scrum 教學,教學書和[官方指南](https://scrumguides.org/)已經寫得很好。這裡寫的是書上的觀念,落到一個真實團隊之後長什麼樣子。

每篇的結構:

1. **我們怎麼做** — 一個實際在跑的做法
2. **為什麼有效,或為什麼不夠** — 對照書裡的觀念
3. **提煉原則** — 一句話能帶走的提醒

## 規劃中

- 看板:不用再問「誰在做什麼」
- 雙週 Demo:定期交付,定期拿回饋
- 少了 Planning 和 Retro 的團隊:只有日常消化,沒有衝刺感
- Demo、Retro、Planning 綁在同一個下午
- Side project 也能用的簡化版 Scrum
