# 第一課：Call help 的能力 ——公園裡的管理課

週末在公園,看到一位媽媽帶著小孩玩。小孩很皮,把外套甩到了樹上。

外套掛得很高。媽媽撿了樹枝,墊腳、伸手、嘗試了很久,怎麼都搆不到。而那個闖禍的小孩呢?在旁邊踢球,完全沒事。

最後媽媽沒能把外套拿下來,生氣地走了。但她的氣不是對孩子發的——她氣的是外套拿不下來,而不是孩子的行為。小孩從頭到尾學到了什麼?什麼都沒有。

做主管七、八年了,看到這一幕才驚覺:這不就是帶團隊的翻版嗎?

成員闖了禍,主管自己扛。技術好、效率高,自己處理比較快——但該承擔的人在旁邊「踢球」,完全不知道發生了什麼事。

過去總以為 call help 是一種示弱——「我做不到,所以需要幫忙。」但其實不是。Call help 有不同的深度:

**第一層:我做不到,所以求助。**
這是大多數人理解的 call help。能力不足,開口請人幫忙。這沒什麼問題,但很多人連這一步都跨不出去。

**第二層:我做得到,但該讓負責的人去承擔。**
這是公園那一幕教我的。如果媽媽讓小孩自己想辦法,小孩也許搆不到、也許會哭、也許得去找路人幫忙——但他會記住這個後果。能不能解決問題,從來不是核心。誰來解決,才是。

**第三層:我做得到,但我選擇邀請別人參與。**
能力超群的人,確實可以一個人搞定所有事。以前我也常這樣——自己寫 code 比較快、自己處理比較不會出錯,久了就什麼都攬在身上。但全部自己來,別人就沒有參與感、沒有被需要的感覺。時間久了,不是你難相處,而是大家覺得你不需要任何人——這本身就是一種距離。

關係,是在互動中建立的。不 call help,就沒有互動。

如果那個小孩跑來跟我說:「叔叔,我不小心把外套丟到樹上了,可以幫我嗎?」我一定傾全力幫忙。而且我會覺得這孩子很懂事——他願意面對自己闖的禍,而不是躲在一旁等別人收拾。

反過來,一個人在那邊悶頭硬撐,旁邊的人想幫都不知道怎麼開口。不開口的人,以為自己在扛責任,其實是在拒絕別人的善意。

選擇讓對的人負責,選擇讓身邊的人參與,選擇不把所有人推到門外。
